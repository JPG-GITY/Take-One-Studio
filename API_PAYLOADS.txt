PBR WORKFLOW EXPLANATION:
─────────────────────────
PBR (Physically-Based Rendering) uses 7 texture maps:

1. ALBEDO (Base Color)
   • RGB colors without lighting
   • Pure surface color information
   • No shadows or reflections

2. NORMAL
   • Encodes surface detail
   • Blue channel stores height
   • Fakes geometric detail without polygons

3. ROUGHNESS
   • Grayscale: black=shiny, white=rough
   • Controls specular reflection spread

4. METALLIC
   • Grayscale: black=non-metal, white=pure metal
   • Affects reflection behavior

5. AMBIENT OCCLUSION (AO)
   • Grayscale: shadows in crevices
   • Darkens areas with less light access

6. DISPLACEMENT
   • Grayscale: vertices move based on values
   • Creates actual geometric detail
   • More expensive than normal mapping

7. EMISSIVE
   • RGB color that self-illuminates
   • For glowing materials

STUDIO-GRADE FORMAT:
───────────────────
• EXR format: Industry standard for VFX (preserves color precision)
• 4K resolution: Suitable for hero assets
• Linear color space: Required for physically-plausible rendering
• ZIP compression: Lossless compression maintains quality

OUTPUT FORMATS EXPLAINED:
────────────────────────

1. MAIN VIDEO (previz_hq.mp4)
   • H.265 HEVC codec: 40-50% better compression than H.264
   • 1920x1080: HD resolution suitable for review
   • Use: Review, approval, editorial reference

2. PROXY VIDEO (previz_proxy_sd.mp4)
   • Lower resolution for faster playback
   • Use: Fast iteration, dailies

3. PREVIEW (preview.webm)
   • Web-friendly format
   • Use: Remote collaboration, web delivery

4. FRAME SEQUENCE (EXR frames)
   • Uncompressed individual frames
   • ACES color space: Industry standard for VFX
   • Use: Final compositing, color grading
   • File per frame: frame_0001.exr, frame_0002.exr, etc.

5. MOTION VECTORS (motion_vectors.bin)
   • Optical flow data between frames
   • Use: Relight, re-time, or stabilize shots

6. CAMERA TRACKING (camera_track.json)
   • 3D camera position and orientation per frame
   • Use: Environment replacement, compositing

7. SKELETAL ANIMATION (skeleton.fbx)
   • 3D character rig and animation
   • Use: Import to Maya/Blender for re-animation

QUALITY SCORES:
───────────────

Optical Flow Confidence (0.0 - 1.0):
  0.7-0.8: Acceptable, some motion artifacts
  0.8-0.9: Good, most motion tracked well
  0.9-1.0: Excellent, smooth consistent motion
  
Temporal Consistency (0.0 - 1.0):
  0.7-0.8: Acceptable, minor flicker
  0.8-0.9: Good, mostly smooth
  0.9-1.0: Excellent, perfectly smooth
  
Artifact Score (0.0 - 1.0):
  0.0-0.05: Excellent, no visible artifacts
  0.05-0.10: Good, minimal artifacts
  0.10-0.20: Acceptable, some visible issues
  > 0.20: Poor, consider regeneration

# 🔗 INTEGRATION WITH RAG SYSTEM
# ============================================================================

The APIs work together in this flow:

1. User asks: "I need a rusty metal shader"

2. RAG Engine:
   • Queries Pinecone for "Rusty Sci-Fi Metal Shader" (similarity: 0.89)
   • Generates Maya code using that as reference
   • User can now recreate or import that asset

3. User likes the texture, wants generation:
   • Open Tab 2 (Pre-Production)
   • Enter prompt: "Rusty metal, more intense weathering"
   • Calls generate_seedream_texture()
   • Gets back 4K EXR maps ready to apply

4. Director wants to see motion:
   • Open Tab 3 (SeeDance)
   • Enter: "Show a robot moving like in that texture asset"
   • Calls generate_seedance_previz()
   • Gets back HQ video + frame sequence
   • Frame quality scores decide if it's ready for storyboarding

This demonstrates the complete pipeline from retrieval → generation → 
preview → integration.
